# 按需求选择视觉方向

视觉方向决定人怎样识别和使用整张画面。做成品前，找当前作品值得选择的地方：读者在哪、停留多久、手在做什么、需要比较什么；或希望某段内容让人停下来、亲近、惊讶还是安静地读下去。把最重要的一处落实到真实内容和场景，剩下的可自由探索。

## 找做法，别先贴风格名

按这处需要找实际作品或规范。打开对应界面或规则，指出一个可迁移的做法和使用代价。两份可以来自不同平台、产品或表达媒介，也可以完全由项目已有材料导出。先选两条在这里都说得通的路，再分别摆出真实文字、对象或状态；不要沿着第一份的 HTML 改皮。两个候选允许共用读得顺、用得熟的控件。

- 熟悉、轻量的触屏操作可看 [Apple HIG 的层级与布局](https://developer.apple.com/design/human-interface-guidelines/layout)：内容先于外壳，常见控件按需要出现；小屏或字体放大后仍保持关系。按 Web 使用情境取用，不把系统材质套在整张网页上。
- 频繁比较与反复操作可以看 [Fluent 2 的自适应布局](https://fluent2.microsoft.design/layout)和[抽屉](https://fluent2.microsoft.design/components/web/react/core/drawer/usage)：大屏并排保留上下文，小屏可聚焦一个对象；看做动作时原信息是否还需要留在手边。
- 首次办事、条件有后果，可以看 [GOV.UK 的办事判断](https://design-system.service.gov.uk/patterns/check-a-service-is-suitable/)；表达作品可从作者实际使用的媒介与读序借办法，例如 [SBS《The Boat》](https://www.sbs.com.au/aboutus/2015/04/29/sbs-online-releases-first-ever-interactive-graphic-novel/)让不同叙事材料跟着故事，而不是给作品配一层通用产品外壳。更多按问题取用的依据见[设计指南](design-guidelines.md)。

## 先比较小样，再实现

用同一段实际内容画两份独立小样，至少看第一次接触和一个关键状态；阅读作品可看开头和一次转折。纸稿、图稿、可渲染局部都行，别用两个风格名或两个配色替代画面。窄屏是主要场景时直接用窄屏起稿。隐去风格名，看读者先遇见谁、怎样往下走、哪里能找到结果；也要看字体、密度、材料和强调方式是否给出了不同体验。若两张都回到同一张硬边海报、同一层玻璃、同一种刊物样子，换一个可行的阅读或使用假设，重新起一张。能采用大面积纯色、强直线或鲜艳色时，让它们为这个作品起作用。

选一份符合简报且更能做好那件事的小样。在工作笔记里用一句话写它赢在哪、另一份牺牲了什么。把入选的图或实拍及需保住的具体关系交给实现，例：动作发生时能同时扫到相邻记录；或某句出现时，突然改变原来的阅读节奏。看成品两端与相同状态，构图、比例和反馈走样就回去补；也实际走一次操作，文字链接等轻量做法仍要有合适的点按区、焦点和反馈。只在两案都适合、取舍相近时，可用[独立路线分配](route-exploration.md#可选在探索时给路线一个外部种子)扩大试过的路；最后仍按作品来选。
