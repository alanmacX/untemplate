# Creative pilot: where does a second idea come from?

Compare three prompts within each tool/model on six frozen, synthetic briefs. Each request gets the same facts, must-work contract and output length, and produces two proposals in a fresh context. No arm gets a manually authored route pool or web references. All conditions instruct the same usable outcome and allow established patterns. Curated refs can be studied as a separate lever.

- **Ground (A):** compact v10-style control. Derive two directions from the same facts, outline opening through result, keep project evidence.
- **Reframe (B):** add a search move: identify a plausible hidden assumption about what people came to do or know; test a different interpretation against one piece of evidence; articulate a changed decision and its tradeoff. Keep user requirements.
- **Transfer (C):** same reframe, with comparison of concrete interactions from two other activities. Extract a relation and map it back to a fact; discard it if it offers no benefit. No style names, example sectors, or ready-made patterns in intervention copy.

Primary outcome is a **usable, consequential fork**: both routes respect the brief and one changes the information/decision order, primary user action or where outcome appears, or a concrete figure/ground, type/material or spatial relationship that genuinely serves the project. A different adjective, unit label, chunk order with the same interaction, famous reference name or a second navigation link does not count. Record task coverage and literal contradictions independently (gates); visual-only forks need a concrete material/read-order difference. Secondary: actual linked evidence, named mechanism and traceable transfer, implementation preservation. Concepts are anonymized before coding. Use explicit yes/no with a reason and keep borderline disagreements rather than assuming a taste score is ground truth. No generated-judge score is a human preference observation.

Target engines: GPT-6.2 Sol (fresh Codex subprocess), Qwen3-8B and Gemma 3 4B IT (local Q4_K_M, same provider settings per engine). Report model-level results and interaction between prompt and engine; do not pool away regressions. Local engines use a fixed max token budget and deterministic per-case seed shared across arms. This is a comparison of instructions within an engine; served-model behavior differs by size, inference stack and quantization. Identical gains across all models are not expected or claimed. Six cases per arm is a directional pilot, without population inference.

Promote only changes that either show repeatable cross-engine usefulness with constraints intact or address a known failure without adding a new mandatory workflow. Any finish-quality claim needs real desktop/mobile screenshots and walkthroughs at fixed completion and a blinded comparison with the operation and content kept intact. Phase 1 starts with proposals; Phase 2 carries matched proposals into working pages.
