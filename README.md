# untemplate

Turn vague frontend briefs into designs shaped by the project's actual content and the people using it.

**anti-aidesign** is an instruction pack for design and coding agents. Use it when the brief sets a goal or a vibe and leaves the visual direction open, or when a generated frontend needs to break out of a template. If a designer, design file or required system already sets the direction, follow it.

- Start with the user's situation, real material, and what the user needs to do.
- Explore a different premise when the first options converge; compare working candidates against the same brief.
- Carry a concrete reading, material or spatial relation into the build. Choose type by what people have to read or compare in the real interface.
- Check the finished result on desktop and mobile and walk the core interaction.

The [skill](skills/anti-aidesign/SKILL.md) is the entry point. Keep the folder together so agents can follow its references. For skill-aware agents, add or link that folder in a supported skills directory. For other agents, ask them to read the entry point and follow its linked references for the current brief.

Current checkpoint: **v12**. The design workflow uses ordinary Markdown and no provider-specific controls. The optional browser check uses Python and Playwright.

See the [creative pilot](research/creative-pilot/RESULTS.md) for version-by-version results and the [copy and divergence pilot](research/copy-and-divergence/RESULTS.md) for the no-skill control, removal checks, seeded exploration, Chinese type audit and screenshots.
