# untemplate

Turn vague frontend briefs into designs shaped by the project's actual content and the people using it.

**anti-aidesign** is an instruction pack for design and coding agents. Use it for an open visual brief, an expressive piece with little or no functionality, or a redesign that needs to lose its generic AI look. If a designer, design file or required system already sets the direction, follow it.

- Start with what the visitor might see, read, feel or do. Place real words and material on the screen and choose a visual relationship.
- Explore a different premise when the first options converge; compare working candidates against the same brief.
- Carry a concrete reading, material or spatial relation into the build. Choose type by what people have to read or compare in the real interface.
- Choose visual material before reserving an image slot. Use grounded source material, the object people actually need to see, or a deliberate graphic that expresses something.
- Look at the rendered draft and change something you actually see. Compare the result on desktop and mobile. If there is a workflow, replay it.

The [skill](skills/anti-aidesign/SKILL.md) is the entry point. Keep the folder together so agents can follow its references. For skill-aware agents, add or link that folder in a supported skills directory. For other agents, ask them to read the entry point and follow its linked references for the current brief.

Current checkpoint: **v15.4**. The design workflow uses ordinary Markdown and no provider-specific controls. The optional browser check uses Python and Playwright.
